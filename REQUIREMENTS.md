# ProductAccounting — постановка задачи

## 1. Назначение

`ProductAccounting` — Android-приложение для ручного учёта товаров, их поступления и расхода через позиции меню.

Первая версия должна работать локально и не требовать подключения к интернету.

## 2. Технологический стек

- Kotlin;
- Jetpack Compose и Material 3 для интерфейса;
- Navigation Compose для навигации;
- Room (SQLite) для локального хранения данных;
- MVVM и Repository для организации кода;
- Kotlin Coroutines для фоновых операций;
- Flow для автоматического обновления экранов при изменении данных.

## 3. Основные разделы

В приложении предусмотрено пять основных разделов:

1. **Товары**;
2. **Приход**;
3. **Расход**;
4. **Меню**;
5. **Способы оплаты**.

Импорт и экспорт данных размещаются в настройках или дополнительном меню приложения.

## 4. Функциональные требования

### 4.1. Товары

Пользователь может создавать и просматривать карточки товаров.

Карточка товара содержит:

- автоматически создаваемый идентификатор;
- название;
- единицу измерения.

Количество товара может быть дробным, например `1,5 кг` или `0,25 л`.

### 4.2. Приход

Приход оформляется в виде вкладки (документа).

- При создании вкладки автоматически фиксируется текущая дата.
- Дата вручную не выбирается и не изменяется.
- В одной вкладке фиксируются все товары, поступившие в рамках этого прихода.
- Для одной даты допускается создание нескольких отдельных вкладок прихода.

Каждая строка прихода содержит:

- товар: идентификатор и название;
- количество;
- входную цену.

Каждая строка прихода образует отдельную партию товара. Денежные значения хранятся в минимальных денежных единицах целым числом, чтобы исключить ошибки округления.

### 4.3. Меню

Пользователь может создавать позиции меню и задавать их состав.

Позиция меню содержит:

- автоматически создаваемый идентификатор;
- название позиции;
- одну или несколько строк состава.

Каждая строка состава содержит:

- товар: идентификатор и название;
- количество товара, необходимое для одной единицы позиции меню.

### 4.4. Способы оплаты

Способы оплаты представляют собой плоский справочник.

Каждая запись содержит:

- автоматически создаваемый идентификатор;
- название.

### 4.5. Расход

Расход оформляется в виде вкладки (документа).

- При создании вкладки автоматически фиксируется текущая дата.
- Дата и время вручную не выбираются.
- Время расхода не хранится.
- В одной вкладке фиксируется весь расход, относящийся к этому документу.
- Для одной даты допускается создание нескольких отдельных вкладок расхода.

Каждая строка расхода содержит:

- позицию меню;
- количество позиций меню;
- способ оплаты.

При проведении расхода количество каждого товара определяется по составу выбранной позиции меню.

## 5. Учёт партий и списание

Товары списываются из партий по принципу FIFO: сначала расходуется наиболее ранняя доступная партия.

Порядок выбора партии:

1. дата прихода по возрастанию;
2. автоматически созданный идентификатор строки прихода по возрастанию.

Если остатка одной партии недостаточно, недостающее количество списывается из следующей партии.

Система должна сохранять связь между строкой расхода, использованной партией прихода и списанным из неё количеством. Это необходимо для точного расчёта остатков и себестоимости, а также для корректного изменения или отмены расхода.

## 6. Предлагаемая структура данных

- `Product` — товар;
- `ReceiptDocument` — документ прихода и его дата;
- `ReceiptItem` — строка прихода и партия товара;
- `MenuPosition` — позиция меню;
- `MenuIngredient` — товар и его количество в составе позиции меню;
- `PaymentMethod` — способ оплаты;
- `ExpenseDocument` — документ расхода и его дата;
- `ExpenseItem` — строка расхода;
- `ExpenseAllocation` — распределение списанного товара по партиям прихода.

Все внутренние идентификаторы создаются автоматически. Связи между сущностями строятся по идентификаторам, поэтому переименование товара, позиции меню или способа оплаты не должно нарушать целостность данных.

Даты хранятся без времени.

## 7. Импорт и экспорт

Приложение должно поддерживать два формата обмена данными:

### JSON

- полная резервная копия всех данных и связей;
- содержит версию формата;
- предназначен для восстановления и переноса данных между устройствами.

### CSV

- отдельный файл для каждого основного набора данных;
- предназначен для просмотра и анализа данных в Excel и других табличных программах;
- не является основным форматом полной резервной копии.

Выбор файла для импорта и места сохранения экспорта выполняется через системное окно Android. Для первой версии импорт JSON выполняется как полная замена текущих данных после проверки файла и подтверждения пользователя. Возможность объединения данных может быть добавлена позднее.

## 8. Границы первой версии

В первую версию входят:

- ведение всех пяти справочников и разделов;
- документы прихода и расхода с автоматически фиксируемой датой;
- состав позиций меню;
- локальное хранение данных;
- автоматическое списание товаров по FIFO;
- импорт и экспорт JSON;
- экспорт CSV.

Облачная синхронизация, расширенная аналитика, отчёты и дополнительные способы расчёта себестоимости не входят в первую версию и могут быть добавлены позднее.
